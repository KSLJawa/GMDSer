1. **宏观调控与暗中通胀控制**：
    - **现象**：发现“特勤处标价（基准价）”是动态变化的
    - **本质**：官方在通过调整基准价，暗中干预市场。当某物品局内产出过多导致物价崩盘时，官方会下调基准价；当某物品稀缺时，上调基准价。这比直接修改爆率更平滑，不会引起玩家对“暗改爆率”的强烈反弹。
2. **基于物品价值的“差异化税率/限价”**：
    - **现象**：全局默认浮动 ±16.6%；个别硬通货经**物品级覆写**可达 +214.2%（极端案例）
    - **本质**：
        - **高价值/硬通货物品（如红、卡、曼德尔砖）**：极易被用于线下RMT洗钱。官方会对其施加**更严格的价格管制**（缩小浮动区间）和**更高的隐性交易摩擦**，切断工作室洗钱链路。
        - **基础刚需消耗品（如高级子弹、药品）**：为了保证底层玩家的生存体验和市场流动性，官方会**放宽价格限制**，甚至降低实际交易摩擦，鼓励玩家自由交易。
3. **物品生命周期管理**：
    - 随着赛季推进，某些旧装备被淘汰，官方会通过调整其基准价和交易参数，加速其在市场中的淘汰或将其转化为底层玩家的保底收益。

通过实测，发现交易行并非简单的全局规则驱动。逆向推导了其底层的数据结构，这里认为官方采用了 **‘全局默认配置 + 物品级覆写 + 赛季动态系数’** 的三级配置表架构。这种设计既保证了基础规则的稳定性，又赋予了策划对单一物品经济表现进行精细化微操的能力，有效平衡了防洗钱与促流通的矛盾。


交易行 tax 与保证金＝**哈夫币的刚性 Sink**，是 03 哈夫币视角里最重要的排水口之一；高价值品高摩擦＝在 Sink 端再加一道反洗钱闸。

> [!warning] 数值订正（早期统计有误，以实测+检索为准）
> 下列 `base_tax_rate=0.02 / deposit_rate=0.05` 仅为**结构占位**，非真实全局值。
> 实测/检索：交易行手续费≈15%、税≈10–11%、保证金≈3–4%[[19]]；
> 且**逐物品不同、随市场动态浮动**（偏离标准价越多税越高[[21]]，印证下方三级配置表的
> `override_tax_rate` 与 `dynamic_price_multiplier` 字段确为必需，而非冗余）。
> 集市侧 P2P 税＝**报价的5%**（前辈实测一单），手续费〔空〕。
> 故 model 的"架构"可信，"default 数值"不可直接引用。

**复杂数据，不具有时效性，此为流程循环：[[交易行调控黑盒]]**


```python
# 1. 全局默认配置表 (Global Default Config)
# 策划在后台配一套默认值，适用于所有未特殊指定的物品
class GlobalTradeConfig(models.Model):
    config_id = models.CharField(primary_key=True, default="DEFAULT")
    base_price_ratio = models.FloatField(default=1.0, verbose_name="全局默认基准价系数")
    min_price_limit = models.FloatField(default=0.167, verbose_name="全局默认最低限价比例")
    max_price_limit = models.FloatField(default=2.166, verbose_name="全局默认最高限价比例")
    base_tax_rate = models.FloatField(default=0.02, verbose_name="全局默认交易税率")
    deposit_rate = models.FloatField(default=0.05, verbose_name="全局默认保证金比例")

# 2. 物品级覆写配置表 (Item-Specific Override Config)
# 针对需要“微操”的物品，配置专属参数。未配置的字段，自动继承全局默认值。
class ItemTradeOverrideConfig(models.Model):
    item_id = models.CharField(primary_key=True, verbose_name="物品ID")
    item_tier = models.CharField(verbose_name="物品价值层级(T0/T1/T2)")
    
    # 以下字段允许为空(Null)，为空则读取 GlobalTradeConfig
    override_base_price = models.IntegerField(null=True, blank=True, verbose_name="覆写: 绝对基准价(覆盖全局系数)")
    override_min_limit = models.FloatField(null=True, blank=True, verbose_name="覆写: 最低限价比例")
    override_max_limit = models.FloatField(null=True, blank=True, verbose_name="覆写: 最高限价比例")
    override_tax_rate = models.FloatField(null=True, blank=True, verbose_name="覆写: 交易税率")
    
    # 动态调价字段
    dynamic_price_multiplier = models.FloatField(default=1.0, verbose_name="赛季动态调价系数")
    
    
    # 基准价解析优先级链（三级合并规则，补全黑盒的另一半）
def resolve_base_price(item, global_cfg, teqin_price):
    # 1) 物品绝对价覆写优先（直接拍死，不再乘系数）
    if item.override_base_price is not None:
        base = item.override_base_price
    # 2) 否则 = 特勤处标价 × 全局系数
    else:
        base = teqin_price * global_cfg.base_price_ratio
    # 3) 叠赛季动态系数
    base *= item.dynamic_price_multiplier
    # 4) clamp 到限价区间（物品覆写比例优先，否则全局）
    lo = item.override_min_limit or global_cfg.min_price_limit
    hi = item.override_max_limit or global_cfg.max_price_limit
    return clamp(base, teqin_price * lo, teqin_price * hi)
```
